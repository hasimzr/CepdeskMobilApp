# CepDesk — Android

Control your COSMIC desktop from an Android phone or tablet over the same local network. Clipboard access, open windows, an application launcher, media, system controls, commands, a touchpad, a keyboard, and screen sharing come together on customizable canvases.

[Website and downloads](https://cepdesk.hasimozer.com) · [MIT license](LICENSE)

## Usage

1. Download the Android APK and the appropriate CepDesk desktop package for your computer from the website.
2. Set the initial connection password in the CepDesk management window on COSMIC.
3. Connect your phone to the same local network. Select your computer in the app, enter the password, and tap **Connect and remember**. If discovery does not work, you can enter the IPv4 address manually; the default port is `43821`.

No cloud account or internet connection is required during use. Initial pairing uses a password proof; subsequent connections use a device key and a pinned TLS certificate. The shared password is not stored on the phone. Keep the desktop and Android versions up to date together. Host requirements, such as uinput permissions for the touchpad/keyboard and ffmpeg/libx264 for H.264, are covered in the desktop documentation.

## Repository layout

This repository contains only the Android app; desktop and web sources are not required to build it. Run all commands from the root of this repository.

- `src/`: React Native / TypeScript interface, connection handling, and canvas management.
- `modules/cepdesk-native/`: native Kotlin Expo module for TLS, discovery, audio/video, and file operations. **The `android/` sources in this directory must be kept in the repository.**
- `plugins/withCepDesk.js`: config plugin that generates Android manifest and splash screen settings.
- `assets/`: icons and splash screen images.
- `tests/`: TypeScript unit tests. Kotlin tests are in the native module's `android/src/test/` directory.
- `scripts/`: standalone APK build script.
- `android/`, `ios/`, `dist/`, `release/`: generated outputs; excluded from Git.

`package-lock.json` is kept in the repository; use `npm ci` to install dependencies. The app uses Expo SDK 54, React Native 0.81.5, and React 19.1. Only Android is currently supported.

## Development

Node.js **20.19.4 or later**, npm, Android Studio / Android SDK, and a suitable JDK are required. JDK 17 or 21 can be used. Local builds use SDK platform 36, build-tools 36.0.0 (Gradle may also request 35.0.0), NDK 27.1.12297006, and CMake 3.22.1. Set `ANDROID_HOME` to your Android SDK path and, if needed, `JAVA_HOME` to your Java installation path. The repository does not depend on a `.tools` directory or any particular parent directory layout.

```sh
npm ci
npm run android:prebuild
npm run android
```

For subsequent Metro sessions:

```sh
npm start
```

**Expo Go is not supported.** The native Kotlin module requires a development build or APK. You can use a physical device with USB debugging or an emulator. Access to your computer's local network depends on the emulator's network configuration.

The root `android/` directory is generated by Expo prebuild. Make persistent Android changes in `app.config.ts`, `plugins/`, or the native module sources. Manual changes in the generated project may be lost during a clean prebuild. The native module is discovered automatically through `nativeModulesDir: ./modules` in `package.json`.

## Checks

```sh
npm run check
```

This runs TypeScript checks, ESLint, TypeScript tests, and an export of the Android JavaScript bundle. The JavaScript export does not replace an APK or Kotlin build.

For native Kotlin tests, run prebuild first:

```sh
npm run android:prebuild
./android/gradlew -p android :cepdesk-native:testReleaseUnitTest --no-daemon
```

The password test vectors and `pinned.pem` under `modules/cepdesk-native/android/src/test/resources/` are public test data, not real user passwords, device keys, or production certificates.

## Building an APK

In a Linux / Bash environment, with dependencies and the Android SDK ready:

```sh
npm run android:release
```

The script runs prebuild, builds the release APK, runs Kotlin tests, and copies the result to `release/CepDesk.apk`. The default architectures are ARM64 and x86_64. If needed:

```sh
CEPDESK_ANDROID_ARCHITECTURES=armeabi-v7a,arm64-v8a,x86,x86_64 npm run android:release
```

The initial download of SDK tools and Maven/Gradle dependencies requires internet access. The JavaScript bundle is included in the release APK; the installed app does not require Metro.

### Signing and distribution

The default local release configuration generated by Expo may use a test/debug key. **Use your own signing key for ongoing APK updates or store distribution.** Do not commit your keystore or passwords. To preserve signing changes in the generated `android/` files, use your own config plugin or configure signing through EAS.

EAS is optional. After configuring it with your own Expo project and signing credentials:

```sh
npx eas-cli build --platform android --profile preview
```

The profiles in `eas.json` produce APKs; the current `production` profile is not an AAB profile for the Play Store. Distribute built APKs through GitHub Releases rather than storing them in the source Git history. The application ID is currently `dev.cepdesk.mobile`; finalize your permanent ID before publishing. Changing the ID or signing key affects updates to existing installations.

## Publishing to GitHub

Place the **contents** of this directory at the repository root: `package.json`, `package-lock.json`, `app.config.ts`, `modules/`, `src/`, `plugins/`, `README.md`, `LICENSE`, and `.gitignore` should be at the root.

`node_modules/`, the generated root `android/` and `ios/` directories, `.expo/`, Gradle caches, APKs, `release/`, and signing files are excluded through `.gitignore`. The `modules/cepdesk-native/android/` sources and public test certificate are retained. GitHub's browser upload does not automatically apply `.gitignore` rules; use a clean source archive or Git commands instead of dragging in the entire working directory.
